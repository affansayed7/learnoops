Note 16 · The one you actually have to DO

Practice & Application 🛠️

15 notes get you to recognize the right answer. This page is where you find out if you can produce it yourself. No quiz here — just work, and a way to get it reviewed.

0 How this page works

  • Work through the tiers in order — each one assumes the skills from the tier before it.
  • Write real code in a real compiler. Don't just plan it in your head — type it, run it, break it.
  • When done (or stuck), paste your code into this chat. Ask for a review "like an interviewer would" — that's the whole point of having Claude alongside these notes.
  • Run the self-review checklist (Section 4) on your own code before asking for a review — catching your own bugs first is a skill in itself.
TIER 1

Warm-ups — one concept each

Small, single-purpose classes. Goal: muscle memory for syntax, not design skill yet.

BankAccount Notes:0307

Private balance. Public deposit(amt) (rejects negative), withdraw(amt) (rejects overdraft, returns bool), getBalance() const.

This one's still owed from earlier in this chat — do it first.

Matrix (Rule of Three drill) Notes:0611

Wraps a dynamically-allocated 2D array (int** or a flat int* with row/col math). Constructor allocates, destructor frees, copy constructor deep-copies. Verify: copy two Matrix objects, modify one, confirm the other is untouched, and confirm no crash on destruction.

Fraction (operator overloading) Notes:10

Overload +, -, *, == as members; overload << as a friend. Store numerator/denominator, don't worry about auto-simplifying unless you want the extra challenge.

Stack<T> (template) Notes:1213

Generic class template: push, pop, top, isEmpty. Then make pop() on an empty stack throw a custom StackUnderflowException instead of undefined behavior — catch it in main().

TIER 2

Small systems — multiple classes working together

Now design judgment matters: what's a class, what's a member, what talks to what.

Shape Hierarchy Notes:080914

Abstract Shape with pure virtual area() const and a virtual destructor. Derive Circle, Rectangle, Triangle. Write a function taking const vector<unique_ptr<Shape>>& that sums total area.

  • Self-test: what happens if you use vector<Shape> instead of vector<unique_ptr<Shape>>? (You should be able to explain why, not just that it's "wrong.")
Employee Payroll Notes:080914

Employee base (name, id, virtual calculatePay() const). Manager, Developer, Intern derived, each overriding pay differently. A Company class holding vector<unique_ptr<Employee>>, with totalPayroll() const that polymorphically sums everyone's pay.

Library Management System Notes:0713

Book (title, author, ISBN, isAvailable). Member (name, id, list of currently-borrowed books). Library (composition: has books and members) with borrowBook(memberId, isbn) and returnBook(...) — throw a custom exception if the book's already out or doesn't exist.

TIER 3

Capstone — everything at once

One project, most of the syllabus. This is your portfolio piece — the one you can actually talk through in an interview.

Mini Bank System Notes:07080911131415

Abstract Account (encapsulated balance, pure virtual interestRate() const) → SavingsAccount, CurrentAccount with different rules (overdraft allowed on Current, not Savings). A Bank class holding vector<unique_ptr<Account>>. Custom InsufficientFundsException, caught by reference. Overload << to print a statement. Stretch: use the Strategy pattern for interest calculation instead of hardcoding it per subclass, and a Factory to create the right account type from a string.

⚠️ Don't start here. If Tier 1 and 2 felt easy, great — but the capstone is where sloppy habits from skipping earlier tiers show up as real bugs (usually: forgetting a virtual destructor, or slicing a polymorphic object somewhere without noticing).

4 Self-review checklist — run this before asking for a review

💡 Every single item on this list is a real trap covered somewhere in Notes 01–15. If one trips you up, that's not a failure — that's your revision list telling you exactly which note to reread.

5 After the capstone

  • Explain it out loud — walk through your Bank System's design decisions as if an interviewer just asked "walk me through this" with no code in front of them.
  • Do a mock interview round — have Claude ask you questions live and give honest feedback on how each answer would land.
  • Revisit the 4 gaps flagged earlier if you have time before the interview: Object Relationships (association/aggregation/composition/dependency), lvalue/rvalue depth, the four casts as a dedicated topic, and stack/heap fundamentals.
🎯 The single best predictor of how you'll do isn't how many notes you've read — it's how many times you've said an answer out loud before the room that actually counts.
