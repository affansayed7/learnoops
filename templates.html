Templates & Generic Programming 🧬

Write the logic once, let the compiler generate a version for every type you actually use — zero runtime cost, at the price of code bloat and slower builds.

1 Function templates

Definition: a blueprint for generating a family of functions — the compiler stamps out a real, concrete function for each type it's actually called with. This is compile-time polymorphism.
template<typename T>
T maxVal(T a, T b) {
    return (a > b) ? a : b;
}
int main() {
    cout << maxVal(3, 7);         // 7 — T deduced as int
    cout << maxVal(3.5, 2.1);     // 3.5 — T deduced as double, a SEPARATE function generated
    cout << maxVal<int>(3, 7.5);  // forces T=int → 7.5 truncates to 7 → max(3,7) = 7
}
  • Normally the compiler deduces T from the arguments — you don't write <int> yourself.
  • You can force it explicitly with maxVal<int>(...) — useful when deduction would be ambiguous or wrong.
💡 Hook: A template is a cookie cutter for functions 🍪✂️ — one shape, stamped out fresh for each type you feed it.

2 Class templates

template<typename T>
class Box {
    T value;
public:
    Box(T v) : value(v) {}
    T get() const { return value; }
};
Box<int> b1(5);          // compiler generates a distinct Box_int class
Box<string> b2("hello");  // and a completely separate Box_string class
  • Box<int> and Box<string> are genuinely two different types as far as the compiler is concerned — not one flexible type.
  • This is exactly how std::vector<T>, std::map<K,V>, and the rest of the STL work.

3 Multiple & non-type template parameters

template<typename K, typename V>    // multiple type parameters
class Pair {
    K key; V value;
public:
    Pair(K k, V v) : key(k), value(v) {}
    void show() { cout << key << ": " << value; }
};
Pair<string, int> p("age", 25);   // this is literally how std::pair works

template<typename T, int N>         // N is a NON-TYPE parameter — a compile-time constant
class FixedArray {
    T data[N];
public:
    int size() const { return N; }
};
FixedArray<int, 10> arr;   // this is literally how std::array<T,N> works
cout << arr.size();          // 10
🏭 Industry framing: This exact pattern (T + a compile-time N) is std::array<T, N> in the standard library — a fixed-size array with zero heap allocation and known size at compile time.

4 Template specialization

Specialization: providing a completely different implementation for one specific type, while the generic template still handles everyone else.
template<typename T>
class Container {
public:
    void show() { cout << "Generic container\n"; }
};

template<>                          // full specialization syntax
class Container<bool> {
public:
    void show() { cout << "Specialized bool container\n"; }
};

Container<int> ci; ci.show();    // "Generic container"
Container<bool> cb; cb.show();   // "Specialized bool container"
🏭 Real example: std::vector<bool> is a genuine specialization in the standard library — it packs booleans into individual bits instead of full bytes, trading some interface quirks for an 8x memory saving.

5 Templates vs virtual functions — the real comparison

TemplatesVirtual functions
BindingCompile timeRuntime
CostZero — fully inlinableOne indirection (vtable lookup)
Types knownMust be known at compile timeCan arrive later (plugins, dynamic libraries)
Code sizeGrows — one copy generated per type usedOne copy, shared by all subtypes
Needs inheritance?No — works via duck typing (any type with the right operations compiles)Yes — needs a common base class
⚠️ The trap most people don't know: template code is largely only checked when instantiated with a real type. A template function can compile cleanly for years, then suddenly fail — with a long, confusing error — the first time it's used with a type that doesn't support some operation the template silently assumed.
🎯 Interview line: "Templates give compile-time polymorphism with zero runtime cost, at the price of code bloat and slower builds. Virtual functions give runtime flexibility for one indirection. I reach for templates when types are known at compile time, and virtual dispatch when they genuinely aren't — like a plugin system."

★ 30-second revision

  • Function/class templates: one definition, compiler generates a separate concrete version per type used
  • Box<int> and Box<string> are genuinely different types
  • Non-type template parameters (like int N) are compile-time constants, not types — the basis of std::array<T,N>
  • Specialization: template<> class X<bool> {...} — a totally custom implementation for one specific type
  • Templates = zero-cost but compile-time-only, code bloat. Virtual = runtime-flexible but one indirection.
  • Template errors often only surface at instantiation, not at the template's own definition
