Static Members & Object Memory 🧮

Where objects live, how arrays of objects are laid out, and the one variable every object agrees to share — static.

1 How is an object stored in memory?

  • When you create an object, memory is allocated only for its data members — each object gets its own separate copy.
  • Member functions are NOT stored per-object. They exist once in a shared code area; every object calls the same function (the this pointer tells it whose data to use — recall Note 03).
  • So the size of an object ≈ the sum of the sizes of its non-static data members (plus possible padding).
💡 Memory hook: Think of a recipe book in a shared kitchen 📖. Every cook (object) has their own ingredients (data), but they all read from the same single recipe (member function) pinned on the wall.

2 Array of objects — objects in a row 🚋

  • You can create many objects at once using an array. Each element is a full independent object with its own data members.
  • They're stored contiguously in memory — back-to-back, like train coaches.
  • The default constructor runs once for every element when the array is created.
class Employee {
    int id;
public:
    void setId(int x) { id = x; }
    int  getId() { return id; }
};

int main() {
    Employee team[3];              // array of 3 objects
    for (int i = 0; i < 3; i++)
        team[i].setId(101 + i);    // each gets its own id

    for (int i = 0; i < 3; i++)
        cout << team[i].getId() << " ";  // 101 102 103
}
💡 Memory hook: Array of objects = a train 🚋 — each coach (element) is a complete object with its own passengers (data), all linked in a line.

3 Static data member — the shared whiteboard 📋

  • A static data member has only ONE copy for the entire class — shared by all objects, not one-per-object.
  • It exists even before any object is created, and lives until the program ends.
  • Change it through one object → every object sees the new value (they're all looking at the same box).
  • It must be defined once outside the class (to actually allocate its memory).
💡 Memory hook: A static member is a shared whiteboard in an office 📋 — everyone has their own desk (normal data), but there's one whiteboard on the wall that all employees read and update together.

4 Static member function — belongs to the class, not the object

  • A static function belongs to the class itself, so you can call it without any object: Employee::showCount();
  • It has NO this pointer (there's no calling object!), so it can only access static members — never the normal (non-static) data of a specific object.
  • Perfect for operating on class-wide data like a shared counter.
⚠️ Key restriction: a static function cannot touch non-static members (like id or salary) — it doesn't know which object's id you'd mean. It has no this.
🎯 Interview line: "A static member function has no this pointer because it isn't tied to any object; therefore it can access only static data members and other static functions."

5 Putting it together — the Employee counter 👔

A classic real use: automatically count how many Employee objects exist. The constructor bumps a shared count up; a static function reports it.

#include <iostream>
using namespace std;

class Employee {
    int id;
public:
    static int count;              // declaration (shared by all)

    Employee() {                    // constructor
        count++;                    // every new object bumps the shared count
        id = count;                 // give this object an auto id
    }

    static void showCount() {       // static function
        cout << "Employees created: " << count << endl;
        // cout << id;   // ❌ ERROR: static fn can't touch non-static id
    }

    int getId() { return id; }
};

int Employee::count = 0;            // define static member ONCE, outside

int main() {
    Employee::showCount();          // 0  — called with NO object!

    Employee e1, e2, e3;            // 3 objects → count becomes 3
    Employee::showCount();          // 3

    cout << e2.getId() << endl;      // 2  (e2 was the 2nd created)
    return 0;
}

Output

Employees created: 0
Employees created: 3
2
  • Employee::count = 0; — the one-time definition outside the class. Forget this and you get a linker error (very common exam trap!).
  • showCount() runs before any object exists — proof that static members live independently of objects.
  • Each constructor call shares the same count, so it climbs 1→2→3 across all three objects.
🎯 Interview trap: "Where and why do you define a static member outside the class?" — "Because the declaration inside the class doesn't allocate storage; the out-of-class definition (int Employee::count = 0;) gives it actual memory, exactly once, avoiding multiple-definition/linker errors."
💡 Memory hook: The constructor is a turnstile at a stadium gate 🎟️ — every person (object) walking in clicks the counter up by one, and that counter is shared by the whole stadium.
