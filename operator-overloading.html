Operator Overloading ➕

Every operator is secretly just a function with a funny name. Once you see that, the member-vs-friend decision, the pre/post-increment trick, and the self-assignment guard all make sense.

1 The core idea: operators are functions

Definition: Giving an existing operator (+, ==, <<...) a user-defined meaning for your own type. It's compile-time polymorphism — the operator is resolved to a specific function at compile time based on operand types.

a + b literally compiles to a.operator+(b) (member) or operator+(a, b) (free function). That's it — no magic.

💡 Hook: a + b is a.operator+(b) wearing a costume 🎭.

2 Member vs friend — the decision that gets asked

Member functionFriend / free function
Left operandMust be your class (it's this)Can be anything
Must use for= [] () -> (language requires these to be members)<< >>, or when you want symmetry (e.g. 2 + c AND c + 2)
class Complex {
    double re, im;
public:
    Complex(double r = 0, double i = 0) : re(r), im(i) {}

    Complex operator+(const Complex& o) const {   // member: left operand is *this
        return Complex(re + o.re, im + o.im);
    }

    friend ostream& operator<<(ostream& os, const Complex& c) {  // FRIEND — left operand is ostream, not Complex!
        return os << c.re << " + " << c.im << "i";
    }
};
Complex a(1,2), b(3,4);
cout << a + b;   // "4 + 6i"
⚠️ Why << can't be a member: a member operator's left operand must be this. In cout << obj, the left operand is cout (an ostream) — you don't own that type, so you can't add a member to it. It must be a free function, made a friend if it needs private access. This is the single most common reason friend exists.

3 Unary operators & the pre/post-increment trick

class Complex {
    double re, im;
public:
    Complex operator-() const { return Complex(-re, -im); }  // unary minus: zero params as a member
};

Prefix and postfix ++ have the same name — C++ tells them apart with a fake, unused int parameter on the postfix version:

class Counter {
    int val = 0;
public:
    Counter& operator++() {          // PREFIX: ++c — returns reference, no dummy param
        ++val; return *this;
    }
    Counter operator++(int) {     // POSTFIX: c++ — dummy `int` marks it, returns BY VALUE
        Counter temp = *this;   // save old state
        ++val;
        return temp;         // return the OLD value
    }
};
  • The int parameter in operator++(int) is never used — it exists purely so the compiler can tell prefix and postfix apart at the declaration level.
  • Prefix returns by reference (cheap, no copy). Postfix must return by value (the old state, since c++'s value is the value before incrementing) — it's inherently one copy more expensive.
🎯 Interview line: "Postfix increment takes a dummy int parameter purely to distinguish it from prefix — and it must return the pre-increment value by value, which is why prefix is preferred in hot loops when the return value isn't used."

4 operator[] and operator()

class MyArray {
    int data[10];
public:
    int& operator[](int i) { return data[i]; }              // allows arr[i] = 5;   (mutable)
    const int& operator[](int i) const { return data[i]; }  // for const objects — read-only
};
  • Returning a reference is what lets arr[i] = 5; work — you're not returning a copy, you're returning a handle to the actual storage.
  • Both overloads are needed: without the const version, a const MyArray& couldn't use [] at all.
class Multiplier {           // the "functor" pattern
    int factor;
public:
    Multiplier(int f) : factor(f) {}
    int operator()(int x) const { return x * factor; }
};
Multiplier triple(3);
cout << triple(5);   // 15 — calling an OBJECT like a function
💡 Why operator() matters: this is a functor — an object that behaves like a function. It's the mechanism behind custom comparators passed to std::sort, and conceptually what a lambda compiles down to under the hood.

5 operator= — the one that must guard itself

class Buffer {
    int* data; int n;
public:
    Buffer(int n) : n(n) { data = new int[n]; }
    ~Buffer() { delete[] data; }

    Buffer& operator=(const Buffer& o) {
        if (this == &o) return *this;    // ① self-assignment guard
        delete[] data;                     // ② free old memory FIRST
        n = o.n;
        data = new int[n];                   // ③ allocate new
        std::copy(o.data, o.data + n, data);  // ④ deep-copy contents
        return *this;                        // ⑤ return ref → enables a = b = c chaining
    }
};
⚠️ Skip step ① and x = x; breaks: you'd delete[] data, then try to copy FROM the memory you just freed — undefined behavior, garbage data. This exact line is what interviewers look for when they ask you to write operator=.
🎯 Interview line: "I always guard operator= against self-assignment, free the old resource before allocating the new one, and return *this by reference so assignments can chain."

6 operator-> — for smart-pointer-like classes

class SmartPtr {
    Employee* ptr;
public:
    SmartPtr(Employee* p) : ptr(p) {}
    Employee* operator->() { return ptr; }
};
SmartPtr sp(new Employee());
sp->raiseSalary();   // compiler recursively applies operator-> until it hits a raw pointer, then dereferences
💡 This is exactly how unique_ptr and shared_ptr work — they overload operator-> and operator* to behave like raw pointers while managing memory underneath.

7 The rules & limits

  • Cannot overload: .  ::  ?:  sizeof  .* — memorize these five.
  • Cannot invent new operators (like ** for power), change arity (a binary operator must stay binary), or change precedence/associativity.
  • At least one operand must be a user-defined type — you can never redefine what int + int means.
  • Return by value for + (a new object is created). Return by reference for =, +=, << — enables chaining.

★ 30-second revision

  • a + b = a.operator+(b) or operator+(a,b) — just a function call in disguise
  • = [] () -> must be members. <</>> must be free/friend (left operand isn't your type)
  • Postfix ++ uses a dummy int param, returns by value (old state). Prefix returns by reference.
  • operator[] needs both a mutable and a const overload
  • operator() makes an object callable — the functor pattern
  • operator= needs: self-check → free old → allocate new → copy → return *this
  • Non-overloadable: . :: ?: sizeof .*
