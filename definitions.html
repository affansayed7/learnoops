OOP Interview Prep · Note 02

What is OOP? + The Vocabulary

12 terms that appear in every OOP conversation — each with a real-life hook so they never leave your head.

A What is Object-Oriented Programming?

  • A programming style where a program is organized around objects — units that bundle data + the functions that work on that data together.
  • Instead of asking "what steps should I perform?" (procedural), OOP asks "what things exist in my problem, and what can each thing do?"
  • Follows a bottom-up approach: design the objects first, then compose them into the full program.
  • Directly fixes every problem from Note 01: data gets protection, code gets reuse, programs mirror the real world.
🎯 Interview line: "OOP is a paradigm that models a program as a collection of interacting objects, each combining state (data) and behavior (methods), giving importance to data rather than functions."

B Class & Object — the heart of everything

Class — the blueprint

  • A template/design that defines what data and behaviors something will have.
  • No memory is allocated when a class is defined — it's just a plan.

🏠 Real life: an architect's house plan — detailed drawing, but you can't live in it.

Object — the real thing

  • A real instance created from the class. Memory is allocated at object creation.
  • One class → many objects, each with its own copy of the data.

🏠 Real life: the actual houses built from that plan — 50 houses, one plan. Painting one house doesn't repaint the others.

class Car {            // blueprint — nothing exists yet
    int speed;
};

Car bmw;               // object — memory allocated NOW ✅
Car honda;             // another object, separate memory
💡 Memory hook: Class = cookie cutter 🍪✂️. Object = the cookies. You can't eat the cutter — and every cookie can have different toppings.

C What lives inside a class

Data member (attribute / property)

  • The variables inside a class — they hold the object's state.
  • All three names mean the same thing; interviewers mix them freely.

📱 Real life: your phone's battery %, brightness, wallpaper — its current state.

Method (member function / behavior)

  • The functions inside a class — what the object can do, usually operating on its own data members.

📱 Real life: call(), takePhoto(), charge() — the things the phone does.

Constructor & Destructor

  • Constructor: special method that runs automatically when the object is born — used to initialize it. Same name as the class, no return type.
  • Destructor: runs automatically when the object dies — used for cleanup. Written with a tilde: ~Car().

🏨 Real life: hotel check-in (room prepared for you) and check-out (room cleaned after you).

class Car {
public:
    Car()  { /* check-in: runs at birth  */ }
    ~Car() { /* check-out: runs at death */ }
};
💡 Memory hook: Data = nouns, methods = verbs. Constructor = birth certificate 👶, destructor = farewell party 👋 (tilde ~ looks like a waving hand!).

D The 4 Pillars — quick definitions

(Each gets its own deep-dive note later — for now, own the one-liners.)

PillarOne-linerReal-life hook
Encapsulation 🔒 Bundle data + methods together, hide the data from outside access 💊 Capsule — medicine sealed inside; you can't touch the powder directly
Abstraction 🎛️ Show only the essential interface, hide complex implementation 🚗 Car pedal — press to go; fuel injection is not your problem
Inheritance 👪 A class acquires the properties of another class 🧬 Child & parent — you got your surname & features, then added your own
Polymorphism 🎭 One name, many forms — same call, different behavior 🗣️ The word "run" — run a race, run a business, run a program
🎯 Interview trap (asked a LOT): Encapsulation vs Abstraction? — "Encapsulation hides data (how it's stored/protected); Abstraction hides complexity (how it works). Encapsulation is about access control, abstraction is about design simplicity."
💡 Mnemonic: A PIE 🥧 — Abstraction, Polymorphism, Inheritance, Encapsulation.

E The supporting cast

Access specifiers

  • private — only the class's own methods can access. Default for class.
  • public — anyone can access.
  • protected — the class + its derived (child) classes.

🏡 Real life: your bedroom (private) · your living room for guests (public) · the family kitchen — family only (protected).

Base class & Derived class

  • Base (parent / superclass) = the class being inherited from.
  • Derived (child / subclass) = the class doing the inheriting.

Instance & Instantiation

  • Instance = just another word for object. Instantiation = the act of creating one.
🎯 Bonus interview fact: "What's the difference between class and struct in C++?" — Only the defaults, and there are actually two of them: ① member access (class → private, struct → public) AND ② inheritance access (class D : Base inherits Base as private by default; struct D : Base inherits it as public by default). Both flip the same way — private for class, public for struct.
